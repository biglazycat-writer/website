# 静态门户实施计划

独立门户通过 Astro、GitHub Pages 与 Cloudflare 提供产品展示和下载，让访问门户不再依赖授权服务的 VPS。

## 实施步骤

1. 盘点营销门户：产品首页、品牌资源、截图、主题、下载、购买入口、FAQ 和中英文帮助；导航仅设特色、下载、购买、帮助四项。
2. 建立独立 Astro 工程，复制页面资源与内容，移除首页登录态和门户后台 API。
3. 保留原产品介绍 React 组件与动效，Astro 预渲染内容、客户端激活交互；下载、FAQ、导航和帮助使用静态 HTML。
4. 购买价格和地址、下载地址分别放在两个 JSON 文件中，默认手动维护；可选在构建时同步正式 Release 安装包。
5. 将双语帮助拆成可直接访问的独立页面，改写 Markdown 互链，提供菜单搜索。
6. 检查双语路由、资源地址、静态构建和项目路径/域名根路径两种模式。
7. 启用 Pages 的 Actions 发布方式，推送主分支，等待成功后验证线上页面。
8. 验证域名所有权，设置自定义域名、DNS、HTTPS，接入 Cloudflare 并验证缓存命中。

## 迁移范围

| 原项目内容 | 新门户处理 |
| --- | --- |
| 产品特色、真实截图、主题扇面、动效 | 复制组件、样式和图片，改为 Astro React island |
| 品牌图标 | 独立复制到 public |
| 中英文门户与帮助内容 | 独立复制；帮助生成静态路由 |
| 下载接口 | 独立 downloads.json；可选构建时 Release 同步，不调用 VPS |
| 后台价格配置与购买 URL | 独立 purchase.json；从 fastcodeai.xyz 导入实际价格与淘宝购买地址 |
| 登录、注册、个人工作台 | 不在静态站显示账号按钮 |
| 授权、支付与在线书城 | 需要服务端，保留在原 web 项目 |
| 公众号排版、画布、思维导图、PDF 在线工具 | 按用户要求不迁移，完整保留在原 web 项目；新门户不显示在线工具入口 |

原 web 项目不修改，不影响现有授权服务和其他客户端。新项目的源码、资源与依赖都独立维护，没有跨仓库导入。

## 当前交付与待执行

本地营销门户、双语帮助、构建下载脚本和 Pages 工作流已准备。线上推送、Pages 启用、DNS 与 Cloudflare 配置须在具备对应账户访问权限后执行。在线工具、登录、注册与后台服务不属于新门户范围，全部保留在原项目。
